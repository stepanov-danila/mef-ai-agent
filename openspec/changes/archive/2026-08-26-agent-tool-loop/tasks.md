## 4. Agent loop

- [x] 4.1 Implement `backend/src/agent/runAgentTurn.ts` exporting `runAgentTurn(messages: ChatMessage[], options: { systemPrompt: string; tools: AgentTool[]; provider: LLMProvider; maxIterations?: number }): Promise<ChatMessage[]>` per design.md: prepends a system message, calls `provider.complete` with the running messages and each tool's `definition`, and returns immediately (full message list including the final assistant message) when the response's `toolCalls` is empty; verify a unit test with a `ScriptedProvider` returning one no-tool-call response asserts the returned messages end with that assistant message and `provider.complete` was called exactly once
- [x] 4.2 Implement tool-call execution: for a response with `toolCalls`, append the assistant's tool-call message, then for each call look up the matching `AgentTool` by `definition.name`, `execute` it, and append a `role: "tool"` message (`toolCallId`, `name`, and the JSON-stringified result as `content`) before calling `provider.complete` again with the extended message list; verify a unit test with a `ScriptedProvider` scripted for two rounds (first requests one tool call, second has no tool calls) asserts both the tool-call and tool-result messages appear in order in the returned list and `provider.complete` was called exactly twice
- [x] 4.3 Implement multi-round tool calling: verify a unit test scripts three rounds (two rounds each requesting a different tool call, a third with no tool calls) and asserts all four resulting messages (2 tool-call rounds × 2 messages each, collapsed appropriately) appear in the correct order and `provider.complete` was called exactly three times
- [x] 4.4 Implement error feedback for an unrecognized tool name or a throwing/argument-invalid tool: catch the error from lookup/execution and append a `role: "tool"` message whose `content` describes the error instead of propagating it out of `runAgentTurn`; verify a unit test scripts a tool call naming a tool not in the registry and asserts the loop continues (calls `provider.complete` again) with an error-describing tool message, and a second test scripts a tool call whose arguments fail that tool's own validation and asserts the same
